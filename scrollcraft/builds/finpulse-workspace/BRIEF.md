# FinPulse workspace design brief

Self-authored under the user's existing creative delegation. The user requested an impressive, immersive portfolio that does not look generic; an interactive FinPulse at the same level as PeopleOS; larger fonts; and explicitly requested Scroll Craft. These decisions extend the working application rather than replace it with a marketing page.

## Evidence and authored decisions

1. Vibe: precise, tangible, calm, inspectable (authored). User: “dont make it look generic and ai slop looking.”
2. Journey: see the current warehouse; follow an actual delivered event; understand overall quality; examine markets; create a scenario (authored from the requested interactive system).
3. Energy: quiet app chrome, one vivid selected-event surface, calm charts, purposeful action. No extended pinned space.
4. Feeling curve: orientation from real counts; curiosity from a selected event; clarity as its source, disposition and output change under one control; confidence from the shared warehouse; agency from staging a scenario.
5. Signature: the same event ID stays attached while the visitor switches Source, Quality and Output, then opens its real immutable envelope. No scroll triggers data mutations.
6. Range: dense working software with deliberate spatial hierarchy. Preserve readable typography and usable tables.
7. World: distinct operational sections with native scroll, not one continuous camera flight.
8. Assets: existing local brand fonts, real API records, actual browser screenshots and completed Orpheus narration. No generated imagery or external asset spend.

## Peak and ending

Peak: “I could follow the same record all the way back to the original data.” It lives in the selected-event surface, the dominant interactive region on the opening. This compact live surface has no invented scroll span or theatrical hold. The final overview action opens the scenario input; users can stage a real isolated batch.

Tell-someone sentence: “It’s the site where I introduced a bad record, reviewed the correction and watched the warehouse change.”

## Grammar and fingerprint

Live surface. App chrome is real navigation; actual session data supplies the opening. No full-screen marketing scene, kinetic heading stack, video scrub, or scroll-controlled approval. The other seven grammars make reading/watching the main activity, whereas this project is an operating workspace. Differences from the portfolio's project desk: grammar, sidebar navigation, event-driven opening, operational sequence, scenario-input close, record-inspection signature (6/6). PeopleOS uses a readiness/risk lens; compare its completed brief before registering the collection.

## Score and layer contract

| Beat | Device | Purpose |
|---|---|---|
| Orientation | Natural flow | Stable labels and readable counts |
| Record inspection | Pointer/keyboard selection | Change the explanation while retaining one real event ID |
| Data path | Reveal | A subtle progress line indicates the selected processing stage |
| Spatial hierarchy | Restrained parallax | Technical background and rear document edge separate from the stable control surface |
| Consequences | Flow + chart inspection | Compare actual warehouse measures |
| Agency | Form input | Stage a batch and run the pipeline |

The back plane is a technical grid, the mid plane is an offset document edge, and the foreground is semantic event data. Text does not parallax. On phones the label column becomes a compact heading and the inspection surface follows it. Reduced motion removes differential movement while preserving all data and controls. No intentional blank scroll.

## Verification plan

Desktop, 390px and compact 360px, intermediate natural scroll positions, reduced motion, keyboard stage selection and actual payload inspection. Re-run the existing integration suite after changes. Headless checks do not establish real iPhone behavior.
